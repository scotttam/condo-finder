# Trends Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Trends page that shows Claude's top 5 current picks with negotiation angles, plus
market charts computed from the database. Reports run daily and on demand.

**Architecture:**
- `listings/trend_stats.py` computes the chart data and market medians from existing tables.
- `listings/analyst.py` gathers the candidates, calls Claude in two passes, prices the usage,
  diffs against the previous report and saves a `TrendReport`. It runs in a background thread
  under a lock.
- A new view and templates render the page. The scheduler starts the daily report after the first
  scrape of the day.

**Tech Stack:** Django 6.1, SQLite, the `anthropic` Python SDK (1.x), HTMX, hand-built inline SVG
charts, pytest.

**Spec:** `docs/superpowers/specs/2026-09-29-trends-design.md`

## Global Constraints

- Model `claude-opus-5-5`, with adaptive thinking (omit `thinking`; never `disabled` or
  `budget_tokens`). Effort is set explicitly: `medium` for the shortlist, `high` for the ranking.
- Requests go through `client.beta.messages.stream(...)` with `betas=["server-side-fallback-2026-07-01"]`,
  `fallbacks="default"`, `max_tokens=32000` and `output_config={"effort": ..., "format": {"type": "json_schema", ...}}`.
- Check `stop_reason == "refusal"` before reading content.
- Cost rates (USD per million tokens): input 4.00, output 20.00, cache read 0.20, cache write 5.00.
- `TRENDS_MANUAL_RUNS_PER_DAY` env setting, default 5. `TRENDS_SHORTLIST_SIZE` = 25, `TRENDS_PICKS` = 5.
- Add migration `0005`; never edit 0001–0004.
- Tests never call the network. The analyst takes an injectable `client`.
- Tests assert on element markup, not bare class names.
- Deliver as stacked PRs `[Trends n/4]`, and update `CLAUDE.md` and `docs/architecture.html` in the stack.

## Review Focus

1. **No API key configured.** The page renders with setup instructions and the Re-run button is
   disabled. The scheduler skips silently. *Test in Task 3 and Task 4.*
2. **Claude returns an id outside the candidate set, or a duplicate.** It's dropped. Ranks are
   renumbered 1..n. *Test in Task 2.*
3. **A picked listing was deleted or went off market after the report.** The card still renders
   from the saved facts and shows "off market". Nothing crashes. *Test in Task 3.*
4. **A report is still running when "Re-run" is pressed, or the daily run fires during a manual
   one.** No second run starts. The page says one is in progress. *Test in Task 2.*
5. **Stats with too little history.** A week with fewer than 3 listings is left out of the charts,
   not drawn as a zero. An empty chart shows "Not enough data yet". *Test in Task 1.*

- Modify: `listings/admin.py` — register both models, read-only
- Test: `tests/test_trend_stats.py`, `tests/test_trend_models.py`

**Interfaces (produces):**
- `TrendReport` fields:
  - `status` (`running`/`done`/`failed`), `trigger` (`auto`/`manual`)
  - `created_at`, `finished_at`, `error`, `model`
  - `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, `cost_usd`
    (Decimal, 4 places)
  - `stats` (JSON), `shortlist` (JSON list[int]), `picks` (JSON list[dict]), `market_read` (text),
    `summary` (text), `changes` (JSON dict)
  - Ordering is `-created_at`.
- `SearchPriorities.get() -> SearchPriorities`: a singleton at pk=1, created on first access.
- `trend_stats.comparable_listings() -> QuerySet[Listing]`: beds ≥ 2, baths ≥ 2, not an apartment,
  price between 1 and `MAX_PLAUSIBLE_RENT`.
- `trend_stats.weekly_series(weeks=8, today=None) -> dict` with:
  - `weeks`: ISO date strings, one per week-ending Sunday
  - `median_rent_by_city`: `{city: [int|None per week]}`
  - `cut_share`: `[float|None]`
  - `median_dom`: `[int|None]`
  - A week with fewer than `MIN_SAMPLE` (3) listings gives `None`.
- `trend_stats.market_snapshot(today=None) -> dict`: current `active_count`, `median_rent`,
  `median_rent_by_city`, `median_ppsf`, `cut_share` and `median_dom`, computed over active
  comparables.
- Active in a given week means `first_seen_at` (or `listed_at`, if earlier) ≤ the week's end, and
  either `is_active` or `last_seen_at` ≥ the week's start. The price at the week's end is the last
  `PriceChange` at or before that time, falling back to `listing.price`. A listing has had a cut at
  the week's end if any earlier price in its current rental period is higher than that week's price.

  - `cut_share` counts a listing after its drop
  - days on market uses `listed_at` when that is earlier
  - apartments are excluded
  - `market_snapshot` medians
  - the `SearchPriorities.get()` singleton

### Task 2: The analyst (PR 2)

**Files:**
- Modify: `pyproject.toml` — `uv add anthropic`
- Modify: `condofinder/settings.py`, `.env.example` — `TRENDS_MANUAL_RUNS_PER_DAY`, plus an
  `ANTHROPIC_API_KEY` hint
- Create: `listings/analyst.py`
- Test: `tests/test_analyst.py`

**Interfaces:**
- Consumes: `default_filter_data`, `ListingFilterForm`, `apply_filters`, `trend_stats.*` and
  `TrendReport`.
- Produces:
  - `analyst.is_configured() -> bool`: true when `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` is set.
  - `analyst.candidates() -> list[Listing]`: default-filter matches plus
    interested/toured/applied, de-duplicated, with `price_changes` prefetched.
  - `analyst.passed_on() -> list[Listing]`: rejected listings.
  - `analyst.compact_facts(listing) -> dict` and `analyst.full_facts(listing) -> dict`; the latter
    adds `description` (truncated to 4000 characters) and `title`.
  - `analyst.run_report(trigger="manual", client=None) -> TrendReport`: synchronous. It creates a
    `running` report and makes both passes. On success it saves `done` with picks, the market read,
    the summary, usage, cost, stats and changes. On any exception it saves `failed` with the error
    and doesn't re-raise.
  - `analyst.start_report(trigger) -> bool`: starts a background thread. It returns False if a run
    is already in progress (checked through the lock and any `running` report younger than 30
    minutes).
  - `analyst.is_running() -> bool`.
  - `analyst.manual_runs_left(today=None) -> int`.
  - `analyst.run_daily_if_due(now=None) -> bool`: starts an auto report when it's configured, no
    auto report exists for today, and nothing is running.
  - `analyst.cost_of(usage) -> Decimal`.
  - `analyst.diff_picks(previous_picks, picks, listings_by_id) -> dict` with `added` (ids),
    `dropped` (list of dicts with id and headline), and `price_moves` (list of dicts with id, from
    and to).
- Pick dicts saved: `listing_id, rank, headline, why, concerns, questions, leverage, offer_low,
  offer_high, price_at_pick, address, photo_url` (the last three are snapshots, so a deleted
  listing still renders).

- [ ] Write tests with a `FakeClient` that records its calls and returns queued JSON responses:
  - two passes, in order, with the correct model, effort, fallbacks and schema
  - the shortlist is filtered to candidate ids
  - picks drop unknown and duplicate ids and are renumbered
  - rejected listings appear in pass 2 but never become picks
  - cost is computed from summed usage
  - a refusal gives a failed report with the error text
  - an exception gives a failed report
  - `start_report` refuses while one is running
  - `manual_runs_left` counts only today's manual reports
  - `run_daily_if_due` runs once per day and not when unconfigured
  - `diff_picks` output
- [ ] Run the tests; they fail. Implement. Run the full suite; it passes. Commit:
  `feat: two-pass Claude analyst for trend reports`.
